## Changed behavior and schema

`NewRequest` accepts only method/path/body. `reply_session` is rejected, not
silently honored. The server shows every generated question in OWNER_AGENT's
Messages and stores its incarnation. The canonical constant in this checkout
was named MRPOPO; it is now OWNER_AGENT, with MRPOPO retained as an alias to
that one definition. Names locate sessions; incarnation IDs bind authority.
Other-session typed input gets a durable request_reply_not_owner_session
outcome without closing the owner window. Non-owner affirmative echoes emit
WARN request_reply_not_owner_input without becoming owner boundary rows.
Application rechecks the owner/question/reply incarnation and the asking actor.
The old own-lane cite exception is superseded for explicit owner-session asks;
passkey mode still needs direct Remote proof. Free-text and asker-selected
session workflows/descriptions are superseded. No schema change: 0124–0130
are untouched (0130 is not present in this checkout).

The class sweep also found that the actual Bash owner CLI omitted the history flag; server-verified owner sends without a relay source now default to recorded history, while an explicit false still opts out.

The class sweep also closes reversed/future clock inputs: timestamps retain
milliseconds, a reply cannot precede its question's clock, and strict row IDs
break equal-clock ties. Stored boundaries and refusal exclusion from B1 stay.
